# Video Thumb Lister 2.0

电影库扫描 / 浏览工具（Python + Tkinter GUI）。

扫描目录生成一份 **JSON 索引**（目录树 + 电影 + 缩略图），然后在图形界面里
像看画廊一样浏览：左侧目录树、右侧缩略图墙，**左键点击直接调播放器播放**，
**右键菜单**可打开所在目录或把电影从列表里剔除。

> 与旧版 `video-thumb-lister` 的区别：旧版输出 HTML 画廊（还要启 HTTP 服务才能
> 点开视频）；2.0 是原生桌面 GUI，索引落在 JSON 里，可增量追加、可剔除、可跨机器搬。

---

## 快速开始

1. 双击 **`启动.bat`**（会自动找 pythonw，无控制台黑窗），窗口**启动即最大化**。
2. 需要本机有 **ffmpeg**（用于抽帧、webp 转 jpg）。程序会依次在以下位置找：
   - 环境变量 `FFMPEG_BIN`
   - `C:/Users/excel/WorkBuddy/Claw/video-ad-cutter/ffmpeg/bin/ffmpeg.exe`
   - PATH 里的 `ffmpeg`
3. 播放器：自动检测 **PotPlayer / VLC**（也可在工具栏手动指定）。

依赖只有 Python 标准库 + Pillow（仅用于把缩略图解码给界面显示）。

## 界面

### Tab ① 扫描 / 生成 JSON

| 功能 | 说明 |
|------|------|
| **① 新建** | 选一个目录 → 递归扫描（含子目录）→ 生成一份新的 JSON |
| **② 追加** | 选一个目录 → 把它**添加进已存在的 JSON**（2.1.2） |

- 扫描过程中为每部电影生成缩略图，规则见下节。
- **电影名 = 视频文件所在目录的目录名**（若该目录直接放视频、无更深的子目录，则退化为视频文件名去扩展名）。**不是视频文件名本身**。
- **JSON 输出位置**：固定落在本项目 `output/` 目录下，文件名按扫描目录自动生成
  —— `gallery_{盘符}_{扫描目录的末级名}.json`（例：扫描 `X:/中文字幕`
  → `output/gallery_X_中文字幕.json`；扫描 `D:/片库/中文字幕`
  → `output/gallery_D_中文字幕.json`）。同一盘符+目录名已存在时追加序号去重
  （`gallery_X_中文字幕_2.json` …）。
- **缩略图只存一份、统一 webp、且只在 JSON 同级目录**：
  - 扫描时直接把缩略图生成到 JSON 同级的 `<json名>_thumb/` 目录里
    （如 `output/gallery_X_中文字幕_thumb/`），文件名形如 `0__动作__ABC-123.mp4.webp`。
  - **绝不会**把缩略图写到视频文件所在目录（避免污染可能在网络盘上的片库）。
  - **封面来源优先级**：
    1. 番号同名的 **webp 封面** → 直接复制为缩略图（保持 webp，原文件不动）；
    2. 番号同名的 **jpg / png / bmp / gif** 等封面 → 用 PIL 转成 webp（原文件不动）；
    3. 都没有 → 用 ffmpeg 从视频**第 10 秒**处抽一帧（片头多为黑场）；
       若**视频时长不足 10 秒**，则直接抽**首帧**。
  - 生成前若 `*_thumb/` 下已有同名的**有效 webp**，则直接跳过、复用已有副本（秒完成）。
  - **浏览界面只读 `*_thumb/` 这一份**（应用内走 PIL→PNG 显示，webp 也能正常显示），
    不去碰可能在网络盘上的视频目录，几千部电影也能秒开。
- 勾选「强制重新生成缩略图」可忽略缓存重跑。
- 支持中途「取消」。

### Tab ② 浏览 / 播放

- **左侧目录树**：整份 JSON 的目录结构，节点上带该目录（含子目录）的电影数量。
  **在目录树上点右键** → 「剔除该目录（含子目录）」：把整支目录从索引里移除
  （同步删除 `*_thumb/` 里这些电影的缩略图），不动磁盘源文件，之后自动刷新。
- **右侧缩略图墙**：列数随窗口宽度自动调整；支持按名称搜索。
- **左键点击缩略图** → 调起 PotPlayer / VLC 播放。
- **右键点击缩略图** → 菜单：
  - **播放**
  - **打开所在目录**（资源管理器打开并选中该文件）
  - **在 JSON 中剔除** —— 只删 JSON 里的节点（**同时删掉 `*_thumb/` 里对应的缩略图副本**），
    **不会删除磁盘上的任何文件**；剔除后目录树与网格自动刷新（目录空了会连带移除空节点）。

快捷键：`F11` 全屏 / `Esc` 退出全屏。

## 缩略图生成规则

按优先级，命中即停止：

1. **同名 jpg 封面** —— 视频同目录存在番号同名的 `.jpg` / `.jpeg`，
   **直接复制**为缩略图（最快，画质最好）。
2. **同名 webp / png / bmp 封面** —— 用 ffmpeg **转码成真正的 jpg** 作为缩略图，
   **原 webp 文件完全不动**（不改名、不改写、不删除）。
3. **都没有** —— 用 ffmpeg 从视频**约第 3 秒**处抽一帧（片头常是黑场），
   宽度缩放到 320px。视频不足 3 秒会自动回退到 1 秒、0 秒。

封面匹配支持「核心番号」：会剥离视频名末尾的版本后缀再找图，
所以封面 `ABC-123.jpg` 同样适用于 `ABC-123.mp4` / `ABC-123R.mp4` /
`ABC-123-U.mp4` / `ABC-123-C.mp4` / `ABC-123-UC.mp4` / `ABC-123-WC.mp4`。

## JSON 结构

**绝对路径只出现在 `settings` 里，目录树内一律相对路径** ——
整个库换台机器、换个盘符，只要改 `settings.roots` 就能继续用。

```json
{
  "settings": {
    "version": "2.0",
    "root":  "D:/Movies",          // 首次扫描目录的绝对路径
    "roots": ["D:/Movies"],        // 所有已扫描根目录（追加扫描会新增）
    "created_at": "2026-09-02T07:45:11",
    "updated_at": "2026-09-02T07:45:11",
    "video_count": 2
  },
  "tree": {                        // 递归目录树，内部全部相对路径
    "dirs": {
      "动作": {
        "dirs": {},
        "files": [
          {
            "name":  "ABC-123",                       // 电影名（去扩展名）
            "file":  "动作/ABC-123.mp4",               // 相对所属 root
            "thumb": "动作/ABC-123.mp4.thumb.jpg",     // 相对所属 root 的源缩略图
            "tfile": "0__动作__ABC-123.mp4.jpg",       // *_thumb/ 缓存副本的文件名
            "size":  2147483648,                      // 字节
            "root":  0                                // 属于 roots[0]（可省略）
          }
        ]
      }
    },
    "files": []                    // 直接位于根层的电影
  }
}
```

追加一个**不在原 root 下**的目录时，会往 `roots` 里新增一条，
该目录的电影记上对应的 `root` 索引，仍然保持相对路径。

JSON 文件名 `<json名>.json` 旁边会有一个同名的 `<json名>_thumb/` 目录，
里面是所有电影的缩略图缓存副本（文件名形如 `0__动作__ABC-123.mp4.jpg`，
由「root 索引 + 相对路径」编码，唯一且 Windows 合法）。浏览界面只读这里。
两份目录（json + `_thumb/`）一起拷贝即可把整个库带走。

## 实现要点（踩过的坑）

- **缩略图显示绕开 ImageTk**：本机「应用程序控制策略」会拦截 Pillow 的
  `ImageTk._imagingtk` DLL，因此走
  `PIL 解码 → PNG bytes → tk.PhotoImage(data=…)`，只用 Tk 自带的 PNG 解码器。
- **ffmpeg 调用必须检查返回码**：`subprocess.run` 默认不检查退出码，
  短视频 `-ss 3` 抽不到帧时 ffmpeg 会「什么都不写却正常退出」，
  导致误判成功。现已 `check=True` + 校验产物是否为真 JPEG，并做 3s→1s→0s 三级回退。
- **相对路径不能用 `os.path.normcase`**：它在 Windows 上会把整条路径转成小写，
  导致 JSON 里存成 `动作/abc-123.mp4`。改用 `os.path.relpath` 保留原始大小写。
- **扫描在后台线程，UI 更新走队列 + `after` 轮询**：绝不在工作线程里碰 Tk
  （Python 3.13 下会触发 `PyEval_RestoreThread` GIL 致命崩溃）。
- **缩略图分批渲染 + LRU 缓存**：大目录不会卡住界面。缓存上限 `CACHE_MAX = 5000`
  （本机 64G 内存，单张约 200KB，5000 张 ≈ 1GB，绰绰有余）；超过即按最近最少用淘汰。
- **浏览只读 `*_thumb/` 缓存副本**：缩略图在扫描时一次性生成并复制到 json 同级的
  `_thumb/` 目录，浏览/刷新界面不再碰可能在网络盘上的视频目录，几千部电影也能秒开。
  剔除电影或目录时会同步删掉 `_thumb/` 里对应的副本。
